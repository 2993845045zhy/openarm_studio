# OpenArm 全链路版本审计（2026-11-17）

> 起因：driver 迁移 + openarm_can 升级后环境里三套 openarm 包并存，
> 多次出现连接失败/姿态错乱/滑块失灵，做一次逐层盘点。

**ROS 2 那条路（另一套，互不冲突但有边界）**：ros2_control 硬件插件
`openarm_hardware/OpenArm_v10HW`（C++），链接的是 openarm_ws 源码树里的
openarm_can 1.1.0（C++ 库），与 pip 的 1.4.1 Python 绑定**无关**。

### 铁律：两条路不能同时对同一机械臂发指令
Studio（driver 直连）和 `start_bringup.sh`/`start_web_panel.sh`（ros2_control）
都会打开 can0/can1。**同时跑 = 真正的"打架"**（两边各 500Hz 轮询+下发）。
开 Studio 前确认 bringup 没在跑：`pgrep -af "ros2|component_container"`。

## 二、版本依赖的三个坑（已踩过，记录在案）

1. **driver 0.5.1 要求 openarm-can>=1.4.0**。之前 pip `--no-deps` 装的
   1.1.0 缺 `ControlMode` 枚举 → 构造函数必炸 → "连接失败"。
   → 已装 1.4.1 修复。
2. **1.4.1 编译需要 CLI11**（1.1.0 不需要）。系统无此包，PyPI 无轮子。
   → 已装到 `~/.local/opt/cli11-prefix`（/tmp 副本重启会丢，以这个为准）。
   重装命令：
   ```bash
   pip install openarm-can==1.4.1 \
     --config-settings="cmake.args=-DCLI11_DIR=$HOME/.local/opt/cli11-prefix/share/cmake/CLI11"
   ```
3. **配置文件**：本机电机零位=URDF 零位（ros2_control 时代的标定约定），必须用**零偏移**配置。
   带工装偏移的 `openarm_cell` 会把姿态整体平移出假角度（"识别的姿不对"的根因）。
   > 更新（2026-11-17 晚）：UI 默认已改为 `openarm_pedestal`（同样零偏移，且限位/增益是
   > 标准版）；四个可选配置见 `driver_arm.CONFIGS`。详见 `~/openarm_ws/docs/OpenArm成果总览_2026-11-17.md`。

## 三、左臂（can1）诊断结论：物理链路无应答，与软件无关

证据链（2026-11-17 上午，多次交叉验证）：

1. 关闭全部软件后裸探测：can0 右臂 10 发 1–2 答、角度真实；
   **can1 左臂 10 发 0 答**，7 轴全静默。
2. 边发边听：can0 上 candump 立刻抓到我们的查询帧（对照成立）；
   **can1 上发帧的同时 candump 一帧都抓不到** → 帧没上总线。
3. 机制：can1 上无节点 ACK → CAN 帧在 PCAN 适配器内无限重传 →
   发送缓冲永久塞满（应用日志 write_no_buffer 单次 +16000）→ 写全丢。
4. 历史统计：can1 自开机（19.7h 前）累计 **RX 728 万包、0 错误** ——
   左臂此前长期正常，静默是最近新出现的。

**→ 需要现场检查（按概率排序）**：左臂供电/电源开关 → 急停按钮 →
CAN 线（can1 那根，PCAN 适配器 channel 2 → 左臂基座）是否松脱。
软件侧已无可疑点；电源/线恢复后无需任何操作，直接连即可。

## 四、软件侧本次修复的三个真 bug（都在 openarm_studio）

1. 滑块部分目标把其余关节填 0 → 起始轨迹姿态下目标跳变超限 →
   官方安全链 force_stop 锁存 → 之后所有指令被拒（"滑块用不了"）。
   → `_to_array` 缺省关节改用当前实测角填充。
2. 大幅拖动/单击滑块凹槽仍可能超单步限幅 → 增加 `_step_toward`
   逐拍逼近（50Hz 重发全量目标，最多几拍走完），永不触发锁存。
3. 若仍出现锁存（导航栏双臂行显示"安全停止"）：失能→使能即可清除
   （start() 会清锁存并把基准设为当前实测角）。
